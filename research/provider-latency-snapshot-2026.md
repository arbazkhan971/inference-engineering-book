# Provider Latency Snapshot, mid-2026: Same Weights, Wildly Different Speeds
researched: 2026-08-27 · researcher: glm-5.3-flash

## Key facts
- Artificial Analysis (AA) benchmarks *endpoints*, not hardware: its "Output Speed" is tokens/sec after the first chunk, and TTFT is seconds from request to first token (first reasoning token for reasoning models); for open-weights models it reports the **median across providers** where no first-party API exists (AA methodology page, fetched 2026-08-27). This median-across-providers design is itself evidence that per-provider latency varies enough to need aggregation.
- Same model, ~6× spread in output speed (derived): **openai/gpt-oss-120b** is listed at ~**3000 tokens/s** on Cerebras public endpoints (Cerebras docs, fetched 2026-08-27) and **500 tokens/s** on Groq (Groq model catalog, fetched 2026-08-27). Derived ratio: 3000/500 = **6×**, same weights, same task.
- Groq published steady-state speeds (Groq catalog, fetched 2026-08-27): Llama 3.1 8B **560 t/s**; Llama 3.3 70B **280 t/s**; gpt-oss-20b **1000 t/s**; Qwen3.6-27B **500 t/s**; MiniMax M2.7 **260 t/s**.
- Cerebras published speeds (Cerebras docs, fetched 2026-08-27): gpt-oss-120b **~3000 t/s**; Gemma 4 31B **~1850 t/s**. Cerebras markets "20× faster than OpenAI and Anthropic" (marketing claim, fetched 2026-08-27, treat as vendor claim not third-party measurement).
- Typical first-party flagship APIs sit far below these numbers; exact August-2026 per-model TTFT/output-speed medians from AA's interactive leaderboards could not be extracted through automated fetch (JS-rendered site), so treat "flagship first-party APIs commonly serve tens of tokens/sec and sub-second-to-several-second TTFT" as a **hedged community characterization, not a sourced number**.
- Prompt caching cuts input processing and cost: OpenAI states caching is "cheaper — pay the cached-input rate, discounted **up to 90%**" and "faster — reduce the time spent processing input before the response starts" (OpenAI prompt caching docs, fetched 2026-08-27). Mechanism: cached KV tensors are reused instead of recomputing the prefix.
- OpenAI cache economics, GPT-5.6-and-later (docs, fetched 2026-08-27): cache write **1.25×** uncached input price, cache read **0.1×**; minimum cacheable prefix **1,024 visible tokens** (2,048 for older models); cached states are machine-local, so traffic above **15 requests/minute** can overflow to machines without the entry and cause misses.
- Anthropic cache economics (docs, fetched 2026-08-27): 5-minute cache writes **1.25×** base input, 1-hour writes **2×**, reads **0.1×**; minimum cacheable prompt length is model-dependent, e.g. **1,024 tokens** for Claude Sonnet 4.5/4.6 and Claude Sonnet 5, **512 tokens** for Claude Opus 5; default TTL **5 minutes**, refreshed on each hit.
- Caching does not change output generation: Anthropic explicitly notes prompt caching "has no effect on output token generation" (docs, fetched 2026-08-27) — so a cache hit shrinks TTFT, not decode speed.
- Cache-hit TTFT reduction is mechanism-driven but rarely published as a number: neither OpenAI nor Anthropic publishes a concrete "TTFT drops by X ms on hit" figure in current docs (both fetched 2026-08-27). The reduction scales with cached prefix length: a hit skips prefill for the entire cached prefix, so longer shared prefixes → larger TTFT savings (mechanism, docs; magnitude unpublished).
- Structured numbers exist and move: AA's own index versioning (Intelligence Index v4.1.1, fetched 2026-08-27) and per-provider price/latency tables change frequently, so any figure quoted from leaderboards must carry a fetch date — this entire digest is a **2026-08-27 snapshot**.

## How it works
Identical weights can be served at very different speeds because output tokens/sec and TTFT are properties of the *serving stack*, not the model file. Providers choose different hardware (GPUs vs Groq's LPU vs Cerebras's wafer-scale engine), different batch sizes (larger batches raise throughput per chip but each user's stream slows), different quantization, and different schedulers. That is why gpt-oss-120b can stream at ~3000 t/s on one provider and 500 t/s on another with the same weights — the spread is the serving engine, not the model.

TTFT decomposes into network + queue wait + **prefill** (processing your whole prompt before the first token can be emitted) + one decode step. Prefill is compute-bound and roughly linear in prompt length, which is why long-context agent prompts (tools, history, documents) dominate TTFT, and why providers serving huge concurrent batches inflate it: your prefill competes with everyone else's work for the same SMs/cores.

Prompt caching attacks exactly that term. When the model processes input it computes key-value (KV) states for every token; a cache hit loads previously computed KV tensors for an identical prefix instead of recomputing them, so TTFT drops by (roughly) the prefill time of the cached portion. OpenAI stores KV tensors on individual machines and routes by a hash of the initial tokens — which is why cache misses appear under load overflow (docs, fetched 2026-08-27). Anthropic's cache requires exact prefix match (tools → system → messages order) with a 20-block backward lookback window, and invalidates everything after the first changed block — a changed tool definition kills the entire cache (docs, fetched 2026-08-27).

## Harness angle
Treat provider choice as a latency-tuning knob, not just a pricing knob: if a workflow runs an open-weights model, benchmark the *same model id* across at least two providers before pinning (the 6× gpt-oss-120b spread between Cerebras and Groq, 2026-08-27 snapshot, is one concrete data point). And build the client to preserve prefix identity — stable tool definitions first, append-only history, stable cache keys — because a mid-conversation tool-schema edit silently reverts you to full-prefill TTFT and 10× input cost on every subsequent turn.
