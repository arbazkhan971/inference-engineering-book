# Costs and Failure Modes of Structured Output: Token Overhead, Constrained-Decoding Tax, and the Quality Tension
researched: 2026-08-27 · researcher: glm-5.3-flash

## Key facts
- "Let Me Speak Freely?" (arXiv:2408.02442, retrieved 2026-08-27): format restrictions measurably degrade reasoning. LLaMA 3 8B on the Last Letter task showed a **38.15% performance gap under JSON format with only a 0.148% parse-error rate** — degradation is behavioral, not a parsing artifact. Ordering across reasoning benchmarks (GSM8K, Last Letter, Shuffled Objects): **JSON-mode (constrained decoding) < format-restricted-instructions < NL-to-format < free natural language**. 100% of GPT-3.5 Turbo JSON-mode responses put the "answer" field before "reason", i.e., the schema silently suppressed chain-of-thought.
- Same paper, GPT-4o-mini via the OpenAI Structured Output API: **natural language still beat JSON-Schema on 2 of 3 reasoning datasets**. Removing the specific schema (asking merely for JSON) improved average scores across Claude 3 Haiku, GPT-3.5 Turbo, and LLaMA 3 8B on GSM8K. On classification tasks, JSON-mode was often competitive or better — the tax is concentrated in reasoning-heavy tasks.
- Grammar-Aligned Decoding (NeurIPS 2024, retrieved 2026-08-27): constrained decoding as commonly implemented **minimizes a different distribution than the model's** — GCD with naive greedy masking steers generation away from the model's preferred token paths, lowering quality; grammar-aligned reweighting restores the intended distribution but is computationally expensive and needs many resamples per prompt to converge.
- CRANE (arXiv:2502.09061, retrieved 2026-08-27): strict grammar-constrained generation on GSM-Symbolic scored **29% vs. 38% for reasoning-augmented constrained decoding (Qwen2.5-Math-7B-Instruct)**, and 9 points below CRANE for Qwen2.5-1.5B — the raw constraint tax is roughly 5–9 points on these setups. Unconstrained CoT at temperature 0.7 needed pass@3 with **~4× more generated tokens** to match CRANE. Theoretical result: constant-depth LLMs under restrictive grammars are limited to TC⁰ — some reasoning problems become provably unreachable under tight grammars.
- The Hidden Cost of Structure (RANLP 2025, retrieved 2026-08-27): across **11 models**, base models often *benefit* from structural constraints while instruction-tuned models are the ones that lose performance — the tax is model-dependent, not universal.
- Capacity, Not Format (arXiv:2606.09410, retrieved 2026-08-27): with information-matched prose controls and a four-level schema complexity gradient across 4 models and 5 benchmarks, format cost tracked **model spare capacity** rather than format per se; models with headroom absorbed JSON schemas at 0% parse failures with little loss, while near-capacity models degraded.
- Latency/throughput tax of constrained decoding: existing grammar-constrained decoding (GCD) methods have per-step overhead that **scales linearly with vocabulary size**, which the PSC paper (arXiv:2608.03065, retrieved 2026-08-27) calls the main throughput limiter for large-vocabulary models; Token Space Compression (arXiv:2605.29986, retrieved 2026-08-27) notes current CFG engines have "intractably high overhead for more complex CFGs — precisely the situation where CFG engines are most useful." Community micro-benchmarks (github.com/JohnScheuer/guided-decoding-bench and github.com/v-code01/constraintcost, retrieved 2026-08-27) measure FSM logit-masking vs. free-decode per-token latency; precise percentage overheads were not reproducible here — treat the qualitative "logit-masking adds per-token latency that grows with mask complexity" as the reliable claim.
- Token overhead of schemas in the prompt: one measured tool schema added **~389 tokens to every request** (Dr Pranay Jha, AI Engineering Series Part 5, retrieved 2026-08-27). Instructor-course documentation (theneuralbase.com, verified April 2026, retrieved 2026-08-27) confirms **every Field(description=...) is serialized into the system prompt regardless of use**, so schema verbosity is a per-request input-token cost; the JSON the model emits is additionally billed as output tokens. JSON's structural tokens (braces, quotes) inflate payload token counts versus prose (MarkDone "Token Tax" tokenizer study, retrieved 2026-08-27 — exact multipliers not verified here).
- Prompt-only JSON ("respond only with valid JSON") fails roughly **1 in 10 times** per practitioner reports (Tanmay Bohra blog, retrieved 2026-08-27; single-source estimate), with failure modes like markdown fences, prose preambles, truncation, and wrong field types.

## How it works
Constrained decoding runs a grammar/FSM/regex at each decoding step: after the model emits its logits, the engine computes which tokens in the vocabulary could legally continue the string under the grammar, masks all others to −∞, then samples. Three cost mechanisms follow:

1. **Compute per step.** Building the legal-token mask requires scanning the vocabulary against the grammar state (or advancing a parser/FSM). Naive engines scale linearly with vocabulary size (often 100k+ tokens) per step, which directly cuts serving throughput and adds per-token latency; the cost grows with grammar complexity (PSC, TSC papers, retrieved 2026-08-27).
2. **Distribution mismatch.** Masking changes the sampled distribution. The model's natural high-probability continuations (e.g., starting a reasoning chain) may be masked out; the engine forces the next legal token even if the model assigned it low probability. Grammar-Aligned Decoding shows this steers generation off the model's intended path; the practical symptom in "Let Me Speak Freely?" is the model filling "answer" before it ever gets to "reason" — because the schema field order forces the conclusion token-first — so measured accuracy drops (38.15% gap on Last Letter) with essentially zero parse errors.
3. **Prompt-side tax.** Whether or not constrained decoding is on, the schema text itself rides in the system prompt every call (~389 tokens measured for one tool schema) and the JSON payload costs output tokens for braces, quotes, and key names that carry no task information.

Worked example (from "Let Me Speak Freely?" Appendix E, retrieved 2026-08-27): a strict regex grader credited GPT-3.5-Turbo only **43.7%** on GSM8K while an LLM parser scored **75.5%** — a 31.8-point gap created purely by over-tight output matching, the same failure family as a too-strict grammar: the constraint, not the model, destroys usable signal.

Repetition loops are an extreme case of mechanism 2: when the grammar forces the model back into a state whose only legal continuations are tokens the model heavily disfavors, it can cycle (coles.codes "repetition trap", retrieved 2026-08-27, documents a vision model that never escapes a grammar-forced loop regardless of sampler settings).

## Harness angle
Default to **free-text (or NL-to-format) generation plus post-hoc parsing/validation/retry for reasoning-heavy steps, and reserve strict grammar-constrained decoding for extraction and classification steps** where the "Let Me Speak Freely?" and CRANE evidence shows the tax is small or absent. Concretely: in the harness config, order schema fields so free-form reasoning fields precede the answer field (or use reasoning-then-constrain decoding); keep schemas minimal (drop Field descriptions from hot-path prompts — they cost input tokens every call); and grade/validate with a tolerant parser, never a tight regex, since a 31.8-point accuracy swing can come from validation strictness alone.
