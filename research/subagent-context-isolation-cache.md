# Subagent Context Isolation as a Cache-Engineering Problem
researched: 2026-08-27 · researcher: glm-5.3-flash

## Key facts
- Prompt caches are **exact-prefix** KV stores: a hit requires 100% identical tokens (including tool definitions and images) up to the cache breakpoint; there is no per-file or per-segment caching (Anthropic prompt caching docs, fetched 2026-08-27; Claude Code prompt-caching docs, fetched 2026-08-27).
- Anthropic pricing multipliers: 5-minute cache writes cost **1.25×** base input, 1-hour writes **2×**, cache reads **0.1×** (≈90% discount) — uniform across the current Claude lineup in the docs table (provider docs, fetched 2026-08-27).
- OpenAI (GPT-5.6 and later) mirrors the arithmetic: explicit cache writes **1.25×**, reads **0.1×** uncached input rate; one write + one full re-read costs **1.35×** vs **2×** for two uncached passes (derived from the multipliers; OpenAI docs, fetched 2026-08-27).
- Minimum cacheable prefix on Anthropic: 512 tokens (Opus 5 class) to 4,096 (Haiku 4.5), model-dependent; shorter prompts silently skip caching (provider docs, fetched 2026-08-27). OpenAI minimum: 1,024 visible tokens for GPT-5.6+, 2,048 for older models (OpenAI docs, fetched 2026-08-27).
- Anthropic allows **up to 4 cache breakpoints** per request (automatic caching consumes one slot); read lookback walks back at most **20 blocks** per breakpoint, so a long-gap conversation can miss its own earlier write (provider docs, fetched 2026-08-27). OpenAI considers up to the latest 50 breakpoints on reads and creates up to 4 writes per request (OpenAI docs, fetched 2026-08-27).
- Invalidation is **hierarchical** in the order tools → system → messages: editing a tool definition invalidates the entire cache; toggling web search or citations invalidates system + messages; changing `tool_choice` or images invalidates only messages (Anthropic docs, fetched 2026-08-27). OpenAI lists `tools`, `parallel_tool_calls`, `text.format`, `reasoning.effort`, and `text.verbosity` as settings that change the rendered prefix and break reuse (OpenAI docs, fetched 2026-08-27).
- Claude Code subagents run in **their own context window** with a custom system prompt and tool subset; the child receives only its own system prompt plus environment details — **not** the parent's conversation — so the child's first request shares at most the system-prompt/tools layers, never the conversation layer (Claude Code subagents docs, fetched 2026-08-27).
- Spawning a subagent in Claude Code **keeps the parent's cache intact** (it's listed under "actions that keep the cache"); subagents get their own cache with a 5-minute default TTL, tunable via `subagentPromptCacheTtl` (v2.1.242+), separate from the main conversation's TTL setting (Claude Code prompt-caching docs, fetched 2026-08-27).
- Claude Code scopes the cache "effectively to one machine and directory": the system prompt embeds working directory, platform, OS, and git snapshot, so sibling subagents in the same directory build matching prefixes and can read each other's cache; sessions in different directories or worktrees cannot (Claude Code docs, fetched 2026-08-27).
- Compaction (summarizing history) invalidates the conversation layer by design — the next request has a new, shorter prefix that matches nothing; `/compact` while cache-warm costs mostly output generation, but cold it reprocesses full history as uncached input (Claude Code docs, fetched 2026-08-27). OpenAI's `context_management` compaction likewise "can prevent reuse from the first changed token onward" (OpenAI docs, fetched 2026-08-27).
- Tool-search / deferred loading is the escape hatch for tool churn: deferred MCP tools connect/disconnect/change without touching the cached prefix; tools loaded into the prefix invalidate everything on any change, including a server silently reconnecting mid-session (Claude Code docs, fetched 2026-08-27).
- OpenAI guidance for agents and forks: put stable developer instructions first, dynamic content last, add explicit breakpoints after each tool result "to improve cache efficiency of forking," and keep a stable `prompt_cache_key` shared across a user's sessions; an illustrative deployment reports a token cache-hit rate >90% (hypothetical figure flagged as such by OpenAI, docs fetched 2026-08-27).
- OpenAI caches live per-machine; traffic above 15 requests per minute can overflow to machines without the entry, so parallel fan-out of subagents can miss even with identical prefixes unless `prompt_cache_key` groups them (OpenAI docs, fetched 2026-08-27).
- Cache-hit arithmetic favors isolating a big shared prefix: with read multiplier 0.1 and write multiplier 1.25, N children reusing one shared written prefix cost `1.25 + 0.1·(N−1)` uncached-equivalents vs `N` fully uncached — for 10 children, 2.15× vs 10× (derived; OpenAI docs formula, fetched 2026-08-27).
- Cross-request concurrency caveat: an Anthropic cache entry only becomes available once the first response begins, so parallel children must stagger behind the parent's write to hit it (Anthropic docs, fetched 2026-08-27).

## How it works
A prompt cache stores the KV tensors the model computed for a rendered prefix — tools, system, messages, in that fixed order. On each request the provider hashes the prefix up to your breakpoint and looks for a matching prior write; on a hit it skips prefill for those tokens and bills them at ~10% of input price. Because the hash is cumulative, one changed token anywhere before the breakpoint changes the hash, and everything after the first divergence is recomputed. This makes "what context does my child inherit" not a memory question but a cache-key question: whatever is byte-identical at the head of the child's request is free-ish, and whatever diverges is full price.

Subagent isolation plays this two ways. A child with its own system prompt and tool subset starts a fresh prefix: it pays a full write for its own head (1.25×) but nothing of the parent's cache is destroyed, and the parent's cache survives because the spawn is just an appended tool call in the parent conversation. If instead the harness makes children share a frozen parent-derived preamble (shared system prompt + stable tool schemas, then the task description as the varying suffix), each child after the first reads that shared prefix at 0.1×. That's the pattern to engineer: identical ordering of tools and system text across all children, breakpoint at the end of the shared block, per-task payload strictly after it.

Forking, editing, and compacting are the three ways harnesses destroy the shared prefix. A fork that rewrites history or inserts a new first message breaks every descendant request from that token onward. Mid-flight edits to tool schemas (a reconnecting MCP server, a permission deny that removes a built-in tool) invalidate the whole cache because tools sit at the head of the hierarchy. Compaction replaces history with a summary — a new prefix that matches nothing — which is fine once but fatal if done repeatedly mid-run. The engineering rule each provider converges on: append, never rewrite; defer tools rather than reshuffling their definitions; put timestamps and per-request data at the tail, behind the last breakpoint.

## Harness angle
Design the subagent spawn contract as a stable-prefix template: a fixed, version-pinned shared preamble (system instructions + tool schemas in a deterministic order) that is byte-identical across all children of a type, with `cache_control` (Anthropic, ≤4 breakpoints) or an explicit `prompt_cache_breakpoint` (OpenAI) on the last stable block and the task prompt strictly after it — and make the child return a compact summary rather than appending its tool debris to the parent, so the parent's cached prefix keeps growing by append only.
